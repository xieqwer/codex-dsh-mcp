# v0.2.0 — 减法更新：只保留「创建并驱动」，补上受限删除

日期：2026-11-09 · 基线：Windows x64 / Node 24.19.0 / DSH 0.2.1-rc.5

## 背景

0.1.0 提供了 6 个工具，其中 `dsh_list_sessions` 和 `dsh_resume_session` 被设计成「访问已有会话」的入口。实际使用中这条路并不可靠：

- ACP 的 `session/resume` 只恢复 DSH 侧上下文，不向客户端回放 transcript；把它当成历史读取并不成立。
- 桌面端仍活跃的会话无法被安全接管（桥接看不到跨进程状态）。
- 恢复旧会话后，DSH 的 deferred tool loading 会让工具历史失效，prompt 直接失败。
- ACP 没有 `session/delete`，桥接创建、桌面又看不到的裸 UUID 会话只增不减。

因此 v0.2.0 做减法：移除 list / resume，只保留「创建会话 → 发消息 → 取消 / 关闭 / 清理」。短期无法实现的历史读取不再保留入口。

## 变更

### 工具目录（v0.2.0）

| 工具 | 映射 | 能力依赖 | 说明 |
|---|---|---|---|
| `dsh_create_session` | `session/new` + `session/set_config_option` | 无 | `cwd` 必须绝对路径且在允许列表内；`model` / `reasoning_effort` 需显式允许 |
| `dsh_send_message` | `session/prompt` | 无 | 显式 `session_id`；单会话单在途 prompt；权限默认 deny |
| `dsh_cancel_session` | `session/cancel` | 无 | 只取消指定会话 |
| `dsh_close_session` | `session/close` | `sessionCapabilities.close` | `confirm=true`；释放运行资源、保留持久历史；能力缺失时隐藏 |
| `dsh_delete_session` | 本地目录删除（无 ACP 方法） | 无 | `confirm=true`；只删本桥接进程创建过的会话；删除前先 close；不读正文 |

已移除：`dsh_list_sessions`（`session/list`）、`dsh_resume_session`（`session/resume`）。

### 删除语义（唯一存储例外）

DSH ACP 未公布 `session/delete`，所以 `dsh_delete_session` 不是 ACP 操作，而是直接删除 `<DSH_HOME>/sessions/<group>/<id>`：

- 只接受当前桥接进程 `#created` 集合中的 session id（进程重启后集合清空，跨进程遗留会话会被拒绝，错误码 `DSH_SESSION_NOT_DELETABLE`）。
- session id 必须匹配 `^[A-Za-z0-9][A-Za-z0-9._-]*$`，拒绝路径穿越（`../`、绝对路径等）。
- 仍在运行的会话先走 `session/close`（需要 close 能力），失败则整体拒绝，不删目录。
- 只做目录删除，不解析 `events.jsonl` / DB / zstd；目录不存在时返回 `DSH_SESSION_STORAGE_NOT_FOUND`。
- 删除不可恢复。

批量清理用 `scripts/prune-sessions.ts`：

- 默认 dry-run，只列出候选，不删除。
- 只删「裸 UUID 且未登记在 `workspace.json`」的会话；`session-*` 桌面会话与所有已登记会话一律保留。
- 只读目录名与 `workspace.json` 登记（`workspace.json` 仅用于安全过滤），不读会话正文。
- `--yes` 才真正删除；删除前再次校验路径位于 `sessions` 根下。

## 未实现项与风险

- **历史读取/搜索**：DSH ACP 与 sdk profile 均无 transcript 回放接口；需要官方 Session Query API 或新的只读扩展。
- **桌面活跃会话接管**：没有跨进程锁/释放确认接口。
- **删除不可恢复**：`dsh_delete_session` / `prune-sessions.ts` 都是本地目录删除，误删无法恢复；脚本因此默认 dry-run。
- **跨进程会话不可操作**：桥接重启后无法继续旧会话（既不能 resume，也不能 delete，因为 `#created` 已清空）；批量清理交给 `prune-sessions.ts`。
- **`usage` 仍为 null**、**仅 Windows x64 真实验证**，与 0.1.0 相同。
